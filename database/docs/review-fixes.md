# Security and lifecycle review fixes

| Original issue | Security / operational risk | Design correction |
| --- | --- | --- |
| `SYN-CASE-001` was closed without `closed_at`. | The seed migration failed once its lifecycle check was applied. | The seed now sets `2026-09-01 08:01:00.000000`; migration 004 also makes the case-state rule bidirectional. |
| OCR had `display_value`. | A routine query or UI log could expose full PII. | Migration 004 renames it to `redacted_display_value`. Only masked text such as `P******7`, `A*** K***`, or `****-**-31` is permitted; full values remain encrypted in `value_ciphertext`. |
| QR token handling was represented only by a case-level hash. | There was no token lifecycle, purpose binding, expiry, device binding, or one-time-use record. | `case_access_tokens` stores only a token hash and tracks issuance, expiry, consumption, revocation, user, device, and purpose. |
| Document files had no quarantine/scan/retention lifecycle. | Unscanned media could be processed, and policy edits could unpredictably change deletion scope. | Each `document_files` row now has storage and malware states, encryption-key reference, and a per-file `retention_until`; purge eligibility uses that timestamp. |
| Issuer codes used two-character country values. | Passport/MRZ/rule lookups need ICAO three-character issuing-state codes, not checkpoint geography codes. | Documents, MRZ records, and rule sets gain `issuing_state_code` (three-character ICAO-compatible). The migration backfills only records derivable from their related document; remaining legacy values require a controlled issuer-code backfill. Checkpoint `country_code` remains ISO alpha-2 geography. |
| Forensic evidence used an unverified object ID; live media had no home. | Evidence provenance was not referentially protected, and selfies could be misclassified as document files. | Findings now foreign-key to `document_files`; `case_media` holds self-captures and case-level media; biometric checks explicitly reference their media/file evidence. |
| Workflow included `deny_entry`. | It could be read as an automatic enforcement outcome despite the officer-assistance policy. | Historical values are migrated to `hold`, and the allowed workflow values no longer include `deny_entry`. |
| The synthetic files were created before lifecycle columns existed. | Their default quarantined state could make synthetic OCR, validation, and forensic fixtures appear to rely on unsafe media. | Migration 005 updates only the four synthetic document-file IDs to approved, `not_applicable`, future-retained demo media with the demo key reference, then requires approved media to be clean or not applicable. |
| Purge items could target only document files. | Selfie/video evidence could miss legal holds, verified deletion, and audit coverage. | `purge_job_items` now permits exactly one document-file or case-media target, with foreign keys and per-job duplicate prevention for both types. |
| Biometric evidence could be incomplete for its check type. | A face match could lack the live or document evidence needed to explain it; liveness could lack a live capture. | A type-specific check requires both sources for `face_match` and case media for `liveness`; the result remains advisory and raw embeddings remain outside plaintext storage. |
| Active rule identity depended on legacy country fields. | Different issuer state/template/rule variants could collide or be published ambiguously. | A generated active-only identity uniquely keys document type, ICAO issuing state, template, and rule version. The backend publishing workflow rejects overlapping effective-date windows. |
| Command-line deployments had no durable migration ledger. | Operators could not prove which exact files and checksums were applied. | `schema_migration_history` records version, filename, SHA-256 bytes, UTC application time, and operator identity; the README defines the bootstrap and per-migration process. |
